## 二·五、尚书省·中枢（桥）——最核心（2026-08-19 主公定）

> **桥（dsh-openai-bridge / server.mjs）是尚书省的心脏**：一切对话与工具调用（出图/QQ/邮件/看板/报告）都经它中转，
> 桥挂 = 全部能力瘫痪。**桥的改进开发 = 改中枢，地位最核心，由尚书省直辖、高于六部**。
> **技能（skill）管理同样归中枢**（2026-08-19 主公拍板·方案A）：技能是桥的能力插件——开发/改进、开源分级、
> 防泄漏检查、GitHub 同步都由中枢直辖；六部只负责**使用**技能生产（如工部用 comfyui 技能出图）。**一句话：中枢管技能，工部用技能**。
> 指挥：「改桥：××」「改技能：××」→ 管家按四步走（备份 → node --check → 重启 → 冒烟验证）改进并呈报。
> 案牍：`04_报告\报错分析报告\`、bridge.log、server.mjs 备份、`skills\README.md`（开源分级清单）。

## 六、日常自救（不用叫管家）

| 情况 | 怎么办 |
|---|---|
| 对话没反应 | 等 30~60 秒（重启后冷启动属正常）；还不行就双击桌面「重启桥」快捷方式 |
| 对话报 [桥接错误] | 截图发给管家，管家查 `bridge.log` 定位（先查后试） |
| 出图失败 | 直接说"出图失败，报错××"，管家查 ComfyUI 日志 |
| 想找旧报告 | 问管家，或直接翻 `{{HANDBOOK_DIR}}\04_报告\INDEX.md` |

## 七、规矩（您的权杖）

1. **重大变更先奏后行**：管家拟方案 → 您拍板 → 才动手（急事可先斩后奏，但必须报）
2. **口令授权制**：涉及 `{{VAULT_DIR}}` 一律要口令「{{授权口令}}」（用户自定义）；管家用后必须报告并登记
3. **注册表/系统级操作**：需要您口头授权，管家不擅动
4. **改律**：章程（守则）修改一律经您批准
5. **交付物**：默认放 `{{DOWNLOAD_DIR}}\`；任务报告存 `{{HANDBOOK_DIR}}\04_报告\`
